## P0（必须先修）

### P0-1 预测分已超过目标，却还显示“还差 28 个考点”
- **问题**：截图 01/10/14（m390）：预测 370（目标 300），“达标把握 92% · 很有把握”，同一张卡又写“离目标还差 28 个考点、约 0.9 小时”。规格 §622 规定 N 是“全部达稳后预测分中值 ≥ 目标所需的最少考点数”，现实现把目标档的全部未稳考点都算进去了（`planner.js:82` remaining 全部计入）。
- **影响**：两个核心数字互相矛盾，用户会怀疑整个系统，“后台替我做决定”的信任就没了；也不知道自己到底要不要继续。
- **建议**：N 改为按 ROI 累加，直到预测中值 ≥ 目标为止；预测下限 ≥ 目标时进入“维持模式”，文案改成“已够线，再稳 X 个考点留出余量”，并且只用一个数据源（见 P0-2 的 `gap`）。
- **改动量**：M　**文件**：`planner.js`（剩余集合）、`engine.js:340` getProgress、`app.js` vToday/vProgress/vResult

### P0-2 新预测分没接入，现在的呈现方式容易让人焦虑
- **问题**：前端仍用旧版 `E.predict()`（Elo θ + 固定半宽 `150/√(1+N/8)`，最小 ±20）。入职测试十几题后就给出“92% 很有把握”。今天页常驻显示分数，每次 5 分钟练习后的结算页也显示（入职 400 → 一次练习后 370，没有任何缓冲文案）。规格 R20 要求的“持平 / 这次难题多，别在意单次”在代码里搜不到。
- **影响**：数字刚上手就过度自信，之后几天一直往下掉，对这类用户打击最大（“又退步了”）。每天盯着分数会把注意力从练习转到焦虑上。
- **建议**：
  1. `api.js` 新增 `API.predict()`：调 `Predict.estimate({log, item, exam, mocks, calib, target, macc, nodes, seed})`，按日志长度缓存；`E.predict` 只作回退。
  2. 呈现分三级，按 `confidence.level`：low 时不给数字，写“再做约 N 题给出预测分”；mid 时只给区间（“约 330–410”）；high 时给中值和区间。一律注明“近似”（`approx`）。
  3. 结算页默认不显示分数，只在上涨 ≥5 分或已跨档时显示一行；下降不显示，统一放进周报，写成“小幅波动，正常”。今天页的分数卡改为“本周趋势：稳 / 上升”，点开才看数字。
  4. `confidence` 不到 mid 时不显示“达标把握 %”；`timeLoss` 和 `gap.nodes[].gain` 用来替代考点数，比如“补好细节题约 +15 分”，比“28 个考点”更有动力。
  5. 补一个真实成绩回填入口（我的 → 考完了？填分数），走 `Predict.calibrate`。
- **改动量**：L　**文件**：`api.js`、`app.js`（vToday 237、vResult 440、vProgress 326、vReviewWeek）、`engine.js` predict、`build.py`（已加载 predict.js）

### P0-3 首日到第一道托业题太长，时长文案还互相矛盾
- **问题**：首日流程是“开始 → 目标表单 → 词汇说明 → 约 47 个词逐个点击（3 分钟）+ 抽查 → 词汇结果 → 诊断说明 → 诊断题 → 结果 → 提醒 → 今天页”。第一道真题之前大约有 50 多次点击、4–5 分钟。文案写法也不统一：今天页和进度空状态写“约 10 分钟”（`app.js:240/325`），诊断按钮写“约 5 分钟”（`:148`），词汇写“约 3 分钟”。
- **影响**：这个人群的抗拒点就是“又要背单词”。先刷词表的感觉最像回到学生时代，首日流失风险最高。
- **建议**：把词汇摸底挪到诊断之后，做成可选项（“补测词汇 3 分钟，推荐更准”，入口 `vre` 已有）。或者把抽查词混进诊断 P5 题里。目标只问一屏（总分 + 考试日期，听力默认按 45% 算）。所有入口统一写“约 X 分钟 · 还差 N 步”。目标是首日第 1 道题出现在 3 次点击、1 分钟以内。
- **改动量**：M　**文件**：`app.js` vOnboard/vVocab/obDone 流程（105–148、699–724）、`UX_SPEC_v1_1.md` §S 流程

### P0-4 每日提醒到点不会提醒
- **问题**：提醒页自己写着“到点后打开应用，今天页会提示你”（截图 00h）。代码里没有 `Notification`、`showNotification` 或 Service Worker 推送，提醒只是用户打开应用后的一条提示（`rmTip`，`app.js:207`）。
- **影响**：用户恰恰是因为忙、会忘才设提醒。现在这个功能形同虚设，回流只能靠用户自己记得。
- **建议**：(a) S：保存提醒时提供“加到手机日历”，生成每日重复的 `.ics`（`RRULE:FREQ=DAILY`，链接直接打开应用），iOS 和安卓都能用，最省事。(b) M：已安装的 PWA 在支持的平台上用 SW `showNotification` 加 Notification Triggers / Push。文案改成“每天 16:30 叫你一声（约 5 分钟）”。不支持时如实说明，并引导用日历。
- **改动量**：S（ics）+ M（通知）　**文件**：`app.js` vRemind/me 提醒行（356、724–728）、SW 文件、`index.html`

### P0-5 手机 P7：浮动切换钮挡住“记下☆”和反馈卡底部
- **问题**：截图 m390/08，`.fab` 固定在右下 52px（`style.css:84`，z-index 15），正好压在“记一招 · 记下☆”按钮上；反馈卡底部的“下一题”也需要滚动才能点到，并且会被它遮住。
- **影响**：关键操作被挡，容易误触（想记招却切到了文章），伤沉浸，也伤效率。
- **建议**：反馈出现后隐藏 FAB，或上移到反馈卡上方；手机端答题后在底部固定一条操作栏 [看原文] [下一题]，FAB 的功能并进去。反馈卡底部留出 `padding-bottom: 80px`。
- **改动量**：S　**文件**：`style.css` .fab/.fb、`app.js` 反馈渲染（546–600）

### P0-6 断签回流没有实现（规格 R21）
- **问题**：`app.js`、`engine.js`、`planner.js` 里都搜不到“欢迎回来”和“首个任务降一档”。断签后顶部变成“本周 N 天”，复习积压平摊虽有，但界面上看不到。离开几天回来，看到的还是普通今天页，复习数可能还变多了。
- **影响**：这类用户一定会断（出差、加班）。第一次回来的体验决定是不是彻底流失。
- **建议**：距上次 ≥3 天时，今天页换成回流卡：“欢迎回来。今天先 3 分钟热身，进度都在。”首个任务时长减半、难度降一档、复习上限先砍到 5；不显示断了几天，不显示积压数量。回流后第 2 天恢复常规。
- **改动量**：M　**文件**：`app.js` vToday、`engine.js` getTodayPlan、`planner.js` reviewQueue（114）

## P1（下一轮）

### P1-1 “28 个考点约 0.9 小时”可信度低
- **问题**：平均每个考点 2 分钟，用户直觉上不信；进度页的“约 0.9 小时 · 照每天 5 分钟约 2 周”是两套口径。
- **影响**：时间承诺不可信，动机反而下降。
- **建议**：主数字用天（“照现在的节奏约 2 周”），小时给区间（“约 1–2 小时”），考点数降为次要信息，或用 P0-2 的 `gain` 改写成“先补 3 项，约 +40 分”。
- **改动量**：S　**文件**：`planner.js:145`、`app.js` vProgress

### P1-2 进度页考点条几乎都满，职级规则和规格不一致
- **问题**：截图 14，“正在攻 3”的三条进度条都接近满格且长度一样，看不出差别。职级按“已稳考点占比”算（`rankOf`，`app.js:300`），规格 §0.5 是按预测分档。
- **影响**：进度感失真：条满了却没“稳”，用户会困惑；职级和分数两套逻辑也互相打架。
- **建议**：进度条按“距稳阈值 0.8”的比例画，并标出阈值刻度；职级改为按预测分档（或在规格里统一改成考点制）。
- **改动量**：S　**文件**：`app.js` vProgress、rankOf

### P1-3 剧情横幅常驻，挤占手机阅读区
- **问题**：P7 手机顶部依次是标题栏 52px、剧情条约 32px、文章/题目切换约 46px、文档标签约 40px，合计约 170px，占 844px 屏幕的 20%。剧情条每篇都重复“运营部群里有几条新消息”。规格要求过渡“只在场景切换时出现、不占位”。
- **影响**：可读行数变少，滚动变多；重复的剧情也会变成噪音。
- **建议**：剧情句显示 2.5 秒后淡出，或收进标题副标题；同一会话只在 Part 切换时出现。手机上把切换按钮和文档标签合成一行（[报道][群聊]｜[题目 1/5]）。
- **改动量**：S　**文件**：`app.js:528`、`style.css` .story/.seg/.dtabs

### P1-4 手机 P7 题文来回切换成本高
- **问题**：双篇 5 题时，每题都要“看题 → 切文章 → 找 → 切回”，`看报道↗` 只解决了定位。
- **影响**：这是注意力消耗最大的场景，也是阅读分的大头（P7 有 54 题）。
- **建议**：文章视图底部常驻一行当前题干（点一下展开选项，半屏抽屉），在文章里就能作答；题目视图保留。左手模式时抽屉跟着换边。
- **改动量**：M　**文件**：`app.js` P7 渲染、`style.css`

### P1-5 次要文字的对比度和字号偏低
- **问题**：`--mut:#6b7280` 在背景 `#f6f5f1` 上对比约 4.4:1，配 `.sm{13px}`，大量用在关键信息上：预测区间、“离目标还差”、剧情句、用时、周报日期。
- **影响**：40 岁以上用户在手机上看吃力，重要信息被做成了“次要”样式。
- **建议**：`--mut` 改为约 `#4b5563`（≥7:1），`.sm` 最小 14px；关键结论不用 `.mut`。复查暗光场景。
- **改动量**：S　**文件**：`style.css:1,6`、`app.js` 中关键 `.mut sm`

### P1-6 多处触控区小于 44px
- **问题**：`.chip` 的 6px padding 高约 34px，`.qnav button` 高 30px，`.mm` 36px，剧情 ✕ 没有设置尺寸，`.dtabs` padding 4px。
- **影响**：误触、点不中，加上老花，挫败感会叠加。
- **建议**：统一 `min-height:44px`，用 hit-slop 伪元素扩大点击区但视觉不变；题号导航 40px。
- **改动量**：S　**文件**：`style.css` 38、62–64、74、126

### P1-7 每题显示“1 秒 · 目标 65 秒”，形成时间压力
- **问题**：P5/P7 反馈卡每题都显示用时和目标秒数；结算页显示“用时 0:00”（短会话时为 0）。
- **影响**：精力有限的用户会被秒数牵着走；“目标”二字像考核。
- **建议**：只在连续偏慢（≥1.5 倍，3 题以上）时给一句建议；提速只在周报里正向呈现。用时不足 1 分钟就不显示。
- **改动量**：S　**文件**：`app.js` 反馈卡、vResult

### P1-8 考前流程薄弱
- **问题**：模考藏在今天页“今天时间多？”的折叠里，一次 75 分钟整块；作战卡只在考前 3 天内上今天页（`app.js:257`）；没有考前节奏提示，没有考试当天卡片，也没有考后回填分数。
- **影响**：最关键的冲刺期反而没有被引导，用户不知道什么时候该做模考。
- **建议**：考试日期已设、且距考试 ≤21 天时，今天页显示一行倒计时和本周重点；T-14/T-7 各推荐一次模考，可拆成 P5+6（约 25 分钟）和 P7（50 分钟）两段；T-1 只做作战卡和轻复习；考试当天显示作战卡 + “考完回来填分数”（接 P0-2 的 calibrate）。
- **改动量**：M　**文件**：`app.js` vToday、`engine.js` mockPlan、`planner.js` 阶段

### P1-9 “记一招”闭环弱
- **问题**：“记下☆”记到了哪里不清楚；入口“我记下的招 · 0”藏在复习页底部；记下的招怎么复习，界面上看不出来。
- **影响**：技巧是这个人群提分性价比最高的抓手，但现在没有回路。
- **建议**：记下后 toast“下次遇到同类题会提醒你”；在同类题出现时题干上方给一行小提示（只给 1 次）；复习页把“记下的招”合进到期卡片，不单独成列。
- **改动量**：M　**文件**：`app.js` 反馈卡/复习页、`engine.js` 复习队列

## 走查结论（首日 → 日常 → 复习 → 考前）
- **首日**：流程完整但太长，词汇摸底放在最前面（P0-3）；提醒页做到了“可跳过”，但提醒本身不会生效（P0-4）。
- **日常**：今天页 1 次点击开始；中断后打开会直接回到原位（`boot` 实现 R1），这点做得好。问题在于数字口径矛盾（P0-1）和分数焦虑（P0-2）。
- **复习**：空状态文案好，没有“逾期”字样；“主管带你练”多选（P2-2），“记一招”没有闭环（P1-9）。
- **考前**：只有考前 3 天的作战卡；模考入口深，没有回填真实成绩（P1-8）。
- **做得好的**：错误色用橙不用红；P5 选项在拇指区；平板答题后在原文下划线标出依据；“看报道↗”只定位不剧透；断签保护 ❄ 自动补签。
