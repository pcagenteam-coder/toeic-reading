# UX v2：面向目标的体验框架（2026-10-24 草案，待 Qing 拍板）

## 1. 为什么 v1 demo 更"惊艳"（对照 work/ux12/cmp/m_all.jpg）
v1 每一屏都在回答"我离目标多远、这一下值多少"：
- 首页大号预测分 200±27 + 目标进度条 + 职级 + 距考天数 + "约 6 小时"。
- 今日任务按"+57 分/时"排序——用户看得见"系统很聪明、我的时间花得值"。
- 答完立刻：对错+用时 → 掌握度 50%→28% → 预测分 250→240 → "计划已调整"。每题都是一次可见的因果。
- 底部导航就是公司 App：收件箱②、改稿③、紧急①，红点 = 待办 = 沉浸。
v1.1/v1.2 为"降压力"把分数、ROI、掌握度变化都藏了，剩下的是一个干净但普通的刷题器。**惊艳感来自"看得见的智能+看得见的进步"，不是装饰。**

## 2. 北极星与体验原则
北极星：用户每投入 1 分钟，预测分涨多少（分/分钟），且愿意明天再来。
1. 目标常在：分数、差距、考试倒计时在首页和结算页始终可见。
2. 每一下都有回报：答题 → 对错 → 掌握度变化 → 预测分变化，三秒内闭环。
3. 智能要被看见：用"为什么现在练这个"一句话 + 分/时 展示 ROI，而不是藏在后台。
4. 世界观即界面：公司 App 是外壳，题型 = 工作场景，红点 = 今日待办。
5. 压力只来自时间，不来自羞辱：计时温和变色；错了说"计划已调整"，不说"失败"。
6. 一个下一步：任何时刻只有一个主按钮。

## 3. 用户旅程（35–50 岁、碎片时间）
| 时刻 | 用户问 | 界面必须回答 |
|---|---|---|
| 首次 3 分钟 | 我现在几分？要多久？ | 入职测试 8 题 → 预测分±区间、目标差距、"每天 10 分钟约 X 周" |
| 每天打开 | 今天干什么？ | 工作台：分数条 + 1 个"开始今天的工作（约 8 分钟）"+ 收件箱红点 |
| 做题中 | 我快不快？对不对？ | 计时、即时对错、一句话为什么 |
| 做完 | 值不值？ | 答对 N/M、用时、预测分 +x、职级进度、明天预告 |
| 一周 | 有没有进步？ | 周绩效：分数曲线、攻下的考点、省下的时间 |
| 考前 2 周 | 够不够？ | 模考 + "已达标/还差 N 个考点" + 冲刺计划 |

## 4. 信息架构（仍 4 入口，但回到 v1 的公司 App 隐喻）
底部：工作台 / 收件箱(P7)② / 改稿(P5·P6)③ / 绩效(进度+复习+设置入口)
- 工作台：分数卡、主按钮、今日 3 项（带分/时）、紧急任务=模考。
- 收件箱/改稿：今天分配的材料以未读邮件/待审稿出现，红点数=今日剩余。
- 复习不单独成 tab：到期复习混入今日工作（"Dana 退回的稿子"）。

## 5. 关键屏规格
- 工作台：v1 布局为底，修 v1 的问题（"实习生/200 分"首日偏打击 → 首日只显示区间+目标，不显示低分大字）。
- 答题后：对错+用时 / 一句话 / 掌握度条动画 / 预测分 ±x / 详解折叠。
- 结算：答对 N/M、用时 vs 参考、预测分变化、职级进度条、"明天：2 封邮件"。
- 模考：真考 75 分钟倒计时，交卷后成绩单+逐题解析。

## 6. 视觉与动效
v1 hark.css 为底：大号数字、留白、黑色主按钮、卡片层次；分数/掌握度变化做 300ms 数字滚动；红点、未读加粗。字号可调。

## 7. 验收（可量化）
- 首页 5 秒测试：看图说出"我几分、离目标多少、下一步点哪"。
- 每题反馈 ≤3 秒内出现对错+分数变化。
- 结算页包含 N/M、用时、分数变化三项。
- 底部 4 项，主按钮唯一；触控 ≥44px；手机单栏、PC 左文右题、离线可用。
